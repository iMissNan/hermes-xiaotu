# free-model-radar v3.0 独立双轨前哨架构设计规范

## 1. 架构核心宗旨与根本纠偏

在过去版本的设计中，雷达曾存在回退读取 10Router 网关本地注册表（如 `/open-sse/providers/registry`）作为候选模型的妥协逻辑。这种逻辑存在根本性缺陷：
- **倒置依赖关系**：雷达本质是行业前哨侦察兵，其使命是**先于 10Router 网关感知外部新货**，并在官方下架时及时预警；如果雷达依赖网关的既有代码，雷达就沦为了网关的“复读机”，彻底丧失了独立发现与前哨巡检的意义；
- **旧账污染**：网关源码中的硬编码列表包含大量历史残留或废弃别名，回退读取会导致模型大盘被历史旧账污染，无法反映厂商当期真实在售货架。

**v3.0 根本纠偏与架构铁律**：
1. **100% 剥离网关旧账依赖**：彻底移除任何扫描 10Router 本地注册表源码文件的回退路径；
2. **直插一手官方前哨**：探针全部直连厂商官方发布的一手信源（官方 NPM 生产发版 Registry、动态推荐 API、官方规约文档与活动站、OpenAPI 兼容端点）；
3. **单向差集对拍与反向赋能**：外部前哨发现最新全量真实原子模型 ➔ 与 10Router 现网已装配模型对拍 ➔ 识别 Dual Matched（双向匹配）、Newly Discovered（新发现漏配）、Ghost Mounted（网关幽灵挂载） ➔ 输出运维决策，反向赋能网关换血升级。

## 2. 四大一手外部探测源规约体系

free-model-radar v3.0 采用元数据配置驱动（`config/vendors.yaml`），将外部探测划分为四大规约策略：

```
                    ┌────────────────────────────────────────────────────────┐
                    │            外部一手前哨探测引擎 (Discovery)             │
                    └────────────────────────────────────────────────────────┘
                                    │
       ┌────────────────────────────┼────────────────────────────┐
       ▼                            ▼                            ▼
【package_introspect】       【dynamic_shelf】             【doc_table】           【openapi】
  - 官方 NPM Registry API      - 客户端推荐动态接口          - 官方规约文档与活动站     - /v1/models 标准端点
  - 提取最新 version/时间      - free/promotional 数组       - HTML 表格/列表模型      - 权威原子模型名录
  - 生产 tarball 核心模型      - OpenRouter :free 池联动     - 0 Credits/限免政策     - (如 NVIDIA NIM, AMD)
  - (如 WorkBuddy 国服/国际)    - (如 Cline Free Tier)       - (如 Qoder 国服/国际)
```

### 策略 1：`package_introspect`（NPM 发版自省）
- **适用场景**：通过 NPM 包分发的现代 AI CLI 客户端（如 WorkBuddy / CodeBuddy）；
- **工作机制**：
  1. 直连官方 NPM Registry（如 `https://registry.npmmirror.com/<pkg>/latest`），获取最新发版版本号（`version`）与发布时间（`publish_time`）；
  2. 提取 `dist.tarball` 下载链接，流式解包读取 `package/product.json`、`package/product.internal.json` 等生产模型清单；
  3. 精准过滤逻辑别名（`default`、`fast-model` 等），提取真实原子模型 ID（如 `deepseek-v4.1-flash`, `hy4-preview`, `glm-5.3-flash`, `gpt-6-astra` 等）；
  4. 解析零倍率/免额模型（如 `credits: "x0.00 credits"`）；
  5. 若遇到极端网络阻断，安全降级至 `fallback_doc_url` 页面正则解析，确保探针永不崩溃。

### 策略 2：`dynamic_shelf`（动态货架）
- **适用场景**：提供实时模型推荐 API 的客户端生态（如 Cline）；
- **工作机制**：
  1. 直连推荐接口（如 `https://api.cline.bot/api/v1/ai/cline/recommended-models`，走本地代理）；
  2. 结构化解析 `free` 数组（真·免费池）与 `clinePass` 数组（促销体验额度池）；
  3. 联动 OpenRouter `/api/v1/models`，提取后缀为 `:free` 的公共免费模型列表。

### 策略 3：`doc_table`（规约表格/列表与活动嗅探）
- **适用场景**：官方维护标准网页文档与限免活动页的供应商（如 Qoder 国服与国际服）；
- **工作机制**：
  1. 并行抓取规约文档（`doc_url`）与限免活动站（`events_url`）；
  2. 解析 HTML 表格或列表中的原子模型名（`DeepSeek-V4-Flash`, `Qwen3.8-Max`, `GLM-5.3` 等）；
  3. 提取官方标称的上下文规格（`200K`, `400K`, `1M`）与限免政策要点（`Qwen3.8-Flash 限时免费使用` 等）。

### 策略 4：`openapi`（标准端点）
- **适用场景**：遵循标准 OpenAI 规范直接暴露 `/v1/models` 端点的供应商（如 NVIDIA NIM、AMD Developer Cloud）；
- **工作机制**：请求官方端点获取 `data` 数组中的模型 ID 清单。

## 3. 纯净网关差集对拍模型

雷达完成一手前哨发现后，将发现的模型集合与 10Router 现网状态进行双向无损对拍：

```
一手外部发现模型 (External Set)                  10Router 现网实际装配 (Gateway Set)
┌─────────────────────────────────┐           ┌─────────────────────────────────┐
│  deepseek-v3-2-volc             │           │  cbai/gpt-5.6-luna (残留)        │
│  deepseek-v4.1-flash  ──────────┼── 匹配 ──┼────────── cbcn/deepseek-v4.1-flash│
│  hy4-preview          ──────────┼── 匹配 ──┼────────── cbcn/hy4-preview        │
│  glm-5.3-flash                  │           │                                 │
└─────────────────────────────────┘           └─────────────────────────────────┘
                 │                                             │
                 ▼                                             ▼
  【Newly Discovered (新发现漏配)】              【Ghost Mounted (网关幽灵挂载)】
  - 外部新出但网关尚未配置                       - 官方已下架但网关仍残留挂载
  - 触发补录提示与前缀挂载建议                   - 触发剔除建议，防止调用黑洞
```

### 网关状态数据源构成：
1. **活跃路由别名**：扫描 SQLite `kv` 表中的供应商前缀别名（如 `cbcn|%`, `cbai|%`, `qdc|%`, `qd|%`, `cl|%`）；
2. **实体连接与锁定制**：扫描 `providerConnections` 表中该供应商各账号下的 `modelLock_*` 字段；
3. **权威暴露端点**：联动查询 `/v1/models` 在线列表；
4. **账号激活透视**：提取该供应商底层账号列表与 `isActive` 状态，当登记账号存在但全部 `isActive=0` 时，触发 `🔴 全未激活预警`，坚决避免将凭据未激活误判为模型下架。

## 4. 四环联动流水线（Pipeline 落地）

当执行 `fm查 <供应商>`（如 `fm workbuddy国服和国际服`）时，流水线按序严格运转：

| 阶段 | 环别 | 责任与输出 |
| :--- | :--- | :--- |
| **环 1** | **官方一手动态前哨探查** | 呈现实时探查证据，明确标明一手来源（如 `官方一手源: NPM 生产发版 (v2.161.1 · 发布于 2026-10-02 01:11)`）、官方当期货架模型清单、限免与规约线索。 |
| **环 2** | **10Router 现网硬核差集对拍** | 输出底层账号激活状态、双向匹配 (Dual Matched)、外部新发现漏配 (Newly Discovered)、网关幽灵挂载 (Ghost Mounted)。 |
| **环 3** | **现场真流量实测与入库快照** | 现场向 10Router 发包打流，精准识别 `🟢 稳活 (200)`、`🟡 额度尽 (402)`、`🔴 下架 (404)`、`🟡 限流 (429)` 与超时，并持久化到本地 SQLite。 |
| **环 4** | **运维决策与换血指引** | 针对幽灵挂载给出剔除建议，针对新发现漏配给出挂载前缀补录建议，并提供一键换血指令。 |

## 5. 核心收益与对比

| 维度 | v2.0 及更早版本 | v3.0 独立双轨前哨架构 |
| :--- | :--- | :--- |
| **信源独立性** | 弱（缺失时回退读取 10Router 源码文件） | **100% 独立于网关**，探针直连官方发版与动态接口 |
| **NPM 自省能力** | 无（无法直接感知 WorkBuddy 等客户端发版） | **内置 NPM Registry + tarball 流式解包**，实时获取版本号与生产模型清单 |
| **前哨感知时效** | 滞后（受限于网关版本或人工跟进） | **零时差**（厂商一旦发版或发布动态推荐，雷达即刻探知） |
| **差集精准度** | 粗粒度 | **细粒度三差集 + Qoder 缩写别名规范化映射** |
| **账号状态诊断** | 仅测模型调用 | **透视底层 providerConnections 账号数与活跃态**，杜绝误判 |
