# 📐 多智能体工作流设计规格

> 💡 **核心定位**：AO 流水线（[[02-Projects/AO-多智能体工作流系统]]）的"图纸标准"——验收怎么写、模型怎么分、审查谁来做。源自 2026-09-11 "工作流强化方案 A"（规格 v1.2，维护者批准落地）。

## 1. 病根与药方（为什么有这套规格）
| 病根 | 药方 |
|---|---|
| 验收员"只按字面判"，标准外缺陷全放行 | 补丁 5：主动扫描四类高危（空值/并发/边界/契约不匹配），抓到即 fail |
| 实施与验收同一个模型=考生自判 | `verify_llm` 顶层键给验收员独立配 Antigravity |
| 步与步之间只有一句仪式性交接 | 派工单/回执全模板 + 每步 :20133 举手汇报 |
| 验收标准全是"文件存在吗" | 验收五断言：**实跑输出、证据路径、边界用例、失败注入、回归对账** |

## 2. 验收模板（A1）全文位置
- **正本**：`~/.hermes/workspace/docs/superpowers/specs/ao-acceptance-template.md`（19 节：铁律墙/五断言/模型分级/红队步/派工单/回执/使用说明/§6.4 择路规则）
- **兜底副本**：`~/.hermes/skills/autonomous-ai-agents/ao-workflow-engineering/references/workflow-hardening-templates.md`
- 铁律墙第一条：**AI 声称的任何"完成/通过/已修复"，必须附可复现命令+原文输出，否则视为未完成。**

## 3. 载体择路规则（§6.4，防止双跑烧 token）
- **能画图纸的走流水线**（AO 工作流）：步骤明确、可静态编排、要断点续跑 → tokenhub 类改造
- **要聊着干的包工头带队**（会话内子代理）：需求还在探索、需要来回对话 → 排障、小功能
- **同一任务 AO 和 SDD 二选一，禁双跑双审**
- 与 superpowers 三技能的关系：requesting-code-review=衔接 / subagent-driven-development=同构择路 / verification-before-completion=理念已移植进铁律墙

## 4. 防模型劫持三件套
1. YAML 每步显式写 `llm.model`（禁靠默认继承）
2. 启动命令显式 `--model`
3. 运行 30 秒内核对进程 cmdline 是否与配置一致
- 模型解析优先级：CLI > shell env > .env > YAML

## 5. 审计方法论沉淀
- `session-claims-audit` 技能（autonomous-ai-agents/ 下）：核查 AI 会话"声称完成"是否属实——物证链：时间线还原 → 引擎手术排查 → 注入消息指纹 → 账本与产物对账
- 配套回归用例：`~/.hermes/skills/autonomous-ai-agents/ao-workflow-engineering/references/test-assets/`（主动扫描诱饵工作流 ×2 + 举手沙箱测试脚本）
