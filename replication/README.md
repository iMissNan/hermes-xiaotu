# 复刻包编写规范（维护者必读）

> 本目录所有指南遵循统一模板与取证纪律。本文件同时是"一个新服务如何进入复刻体系"的流程定义。

## 一、固定模板

每份 `N-组件.md` 按以下八节组织：

```markdown
# N-组件名
> 一句话：它是什么、在架构图里的位置（上下游依赖）。

## 1. 是什么
组件职责 + 为什么需要它（2-4 句）+ 与邻居组件的关系。

## 2. 上游原址
- 项目仓库（GitHub 链接 + 协议 +活跃度）
- 镜像 / npm 包 / 安装源（精确 tag）
- 若是自研/魔改：源码在本仓的路径（assets/ 下）

## 3. 部署
照抄可跑的完整命令（docker run / 安装 / systemd 单元）。
参数逐条带注释；命令从本机实际运行配置导出，禁止凭记忆编写。

## 4. 配置
关键配置文件路径 + 结构说明 + 模板（环境值一律占位符）。
默认口令等敏感值不给真值，给"首次初始化时你自己设置"的指引。

## 5. 数据重建（可换皮核心）
本机有什么数据 → 复刻者如何在自己的环境里重建等价数据。
（注册/向导/导入/自动生长……）不提供数据迁移，只教重建。

## 6. 服务联动
它依赖谁、谁依赖它、断供时的表现与自愈方式。

## 7. 验证
3-6 条可执行的验证命令或操作，与 13-验收清单.md 对应。

## 8. 升级与回滚
拉新版/重打补丁的流程；数据卷是否受影响；回滚路径。
```

## 二、取证纪律（铁律）

1. **一切以实况为准**：部署命令必须来自 `docker inspect`、`systemctl cat/show`、实际配置文件导出，禁止凭记忆或"应该就是"编写；
2. **敏感面三查**：写完每份指南过一遍真值扫描（pre-push 钩子会兜底拦截）——域名/IP/口令/账号/机场名一律占位符；
3. **通用常量白名单**：Docker 网桥 `172.17.0.1`、回环 `127.0.0.1`、文档示例网段 `192.168.10.0/24` 属通用常量可直写；机场节点名、账号、域名属真值必须占位；
4. **上游可访问性验证**：写"从零安装"之前，先确认上游仓库/镜像公网可达（引用不存在的东西=复刻者装不出来）；
5. **双链回写**：指南写完后，回到 `02-Projects/` 对应服务卡加一行"复刻指南 → `[[replication/N-组件]]`"。

## 三、占位符体系

复用全仓统一占位符：`<你的域名>` `<内网IP>` `<内网IP备用>` `<Tailscale IP>` `<统一口令>` `<台账账号>` `<机场A>` `<机场B>` `<出口服务器>`。真实值只存在于本机 `_local/本地环境速查卡.md`（不入库）。

## 四、新增服务入体系流程

1. 取证：`docker inspect` / `systemctl cat` 导出运行实况；
2. 判定上游：开源项目→引上游；自研→源码入 `assets/`；
3. 按模板写 `N-组件.md`（编号按部署依赖顺序插入）；
4. 更新 `DEPLOYMENT.md` 全服务一览表 + 依赖图；
5. 对应服务卡双链回写；
6. 提交（钩子自动过真值扫描）。
